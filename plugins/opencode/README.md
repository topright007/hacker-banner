# OpenCode Sensor

Плагин для **OpenCode 1.18.11, V1 API**. Собирает доступный контекст по контракту
`contracts/classifier/opencode-1.18.11`, вызывает классификатор и удерживает
`tool.execute.before` / `tool.execute.after` до решения пользователя.

Сейчас классификатор — **локальная заглушка, всегда возвращающая `deny`**.
Она не оценивает безопасность и никуда не отправляет данные по сети.
Для подключения настоящего классификатора заменяется адаптер в `src/classifier.ts`.

## Сборка и подключение

Требуются Node.js 22+ и pnpm 11+.

```sh
cd plugins/opencode
pnpm install --frozen-lockfile
pnpm build
pnpm config:print
```

Последняя команда печатает JSON с **абсолютным file URL** собранного плагина.
Добавьте элемент `plugin` в свой `opencode.json`, сохранив остальные настройки.
Перезапустите OpenCode. В уведомлении появится сообщение о включённой заглушке.

Плагин должен быть подключён один раз. Разместите его последним среди плагинов,
меняющих аргументы или результаты. Проверьте также автоматически загружаемые
`.opencode/plugins` и глобальные плагины: их порядок влияет на проверяемое значение.
Плагин не меняет настройки OpenCode автоматически.

Сборка содержит зависимости и копии JSON Schema внутри `dist/index.js`.
Для запуска готового файла дополнительные npm-пакеты не нужны.

## Подтверждение пользователем

При первом отклонении автоматически откроется локальная страница:

- **«Разрешить один раз»** пропускает только показанный checkpoint.
- **«Остановить сессию»** блокирует известное дерево сессий и отправляет запросы
  `session.abort`. Новые tool/model hooks этого дерева остаются заблокированными
  до перезапуска плагина.
- Пока пользователь не ответил, вызов продолжает ждать. Таймаута ответа человека нет.

У одного инструмента **два независимых подтверждения**. Pre разрешает запуск;
post разрешает передать результат агенту. В post инструмент уже выполнился —
отказ не отменяет изменения файлов, запросы сети и другие совершённые действия.

Панель показывает имя инструмента, фазу, аргументы, причину отказа и post-результат.
Большие предпросмотры сокращаются с явной отметкой. Кнопка скачивания полного
запроса позволяет проверить весь контекст и результат до решения.
Для MCP предпросмотр включает содержимое ответа, а не выбирает произвольное поле
`output`: дополнительные поля сервера не должны скрывать данные, передаваемые агенту.

Если браузер не открылся, в уведомлении OpenCode будет путь к `control.json`.
Откройте значение `url` из этого файла в браузере на машине, где запущен OpenCode.
URL содержит секретный ключ доступа; не помещайте его в диалог с агентом.
Панель сохраняет ключ в `sessionStorage` текущей вкладки, чтобы обновление страницы
сохраняло доступ к ожидающим подтверждениям. Если браузер запрещает это хранилище,
ключ остаётся в исходной ссылке для восстановления после обновления.

Панель слушает только `127.0.0.1` на случайном порту. Для headless/remote запуска
нужен доступ пользователя к этой loopback-панели; отсутствие браузера не разрешает
действие автоматически. Штатного произвольного confirmation dialog в V1 API
плагин не имитирует.

## Настройки

Элемент `plugin` может быть парой `[fileURL, options]`:

```json
{
  "openBrowser": true,
  "apiTimeoutMs": 5000,
  "classifierTimeoutMs": 3000
}
```

Опциональный `stateDirectory` — абсолютный путь к отдельной папке для этого
экземпляра плагина. Не используйте одну папку для нескольких одновременных
экземпляров. По умолчанию создаётся уникальная папка в
`~/.local/state/opencode-sensor/<workspace-hash>/<instance-id>/`.

Политика ошибок после успешной инициализации плагина:

- Недоступность/таймаут/некорректный ответ классификатора: **fail-open**, событие
  записывается в журнал. Штатные ограничения OpenCode сохраняются.
- Отказ пользователя, ошибка интерфейса подтверждения или внутренний некорректный
  контракт: **блокировка**. Это не считается недоступностью классификатора.
- Разрешение одного checkpoint не снимает другие ожидающие или окончательные
  блокировки этого дерева.

## Контекст и локальные записи

Собираются текущий вызов, полная доступная сохранённая история дерева сессий,
делегирование, независимые снимки context hooks, доступные registry descriptions,
настройки разрешений и модели, inventories skills/resources, workspace и журнал
наблюдаемых событий/решений. Отсутствующие значения и ошибки API обозначаются
в `availability` и `coverage`; неподдерживаемые поля не подставляются.

В папке состояния:

```text
control.json              приватный адрес панели подтверждения
requests/req_<uuid>.json   полный неизменный запрос на каждый pre/post
decisions.jsonl           решения классификатора и разовые решения пользователя
```

Папка имеет права `0700`, новые файлы — `0600`. Конфигурационные ключи, токены,
значения env и auth headers исключаются из проекций настроек. Исходные сообщения,
аргументы и результаты сохраняются: они сами могут содержать конфиденциальные
данные. Автоматической очистки журналов и ротации пока нет.

Журнал событий в контексте начинается с подключения плагина. Записанные audit-файлы
сохраняются после выхода, но автоматическое восстановление блокировок/наблюдений
после перезапуска не реализовано (`durable_across_restart: false`).

При изменении контракта синхронизируйте встроенные схемы:

```sh
pnpm contract:sync
pnpm build
pnpm test
```

## Проверки

```sh
pnpm test
pnpm typecheck
pnpm format:check
pnpm test:live
```

`test:live` использует установленный dev dependency `opencode-ai@1.18.11`,
локальную детерминированную модель и временный проект. API-ключи и внешний LLM
не требуются. Проверяются разрешение обеих фаз, отказ в pre и отказ в post с
реальными файловыми эффектами и проверкой следующего запроса модели.
Для тестов панели и live-теста нужна возможность слушать loopback TCP.

## Границы V1

- Известный дефект запуска (P1): если инициализация сенсора завершается ошибкой,
  например из-за недоступной папки состояния, OpenCode может продолжить работу
  без его hooks. Этот случай пока не исправлен; политика блокировки выше
  не гарантируется до успешной загрузки плагина.
- Снимки SDK не атомарны. Уже запущенные параллельные действия могут завершиться
  до отмены; вызов abort не откатывает их.
- Обычные ошибки инструментов могут пропускать post hook. Они попадают в
  наблюдаемую историю/события, но это не гарантированный синхронный post gate.
- Нет полного каталога описаний ordinary MCP tools, точного итогового provider
  request и полной sandbox policy.
- Один bash/code-mode вызов может включать много действий. Прямые ручные shell
  пути и другие обходы V1 tool hooks не становятся полноценным системным сенсором.
- Панель с приватным ключом защищена от случайных/внешних запросов, но не является
  границей изоляции против произвольного процесса с полным доступом того же OS-user.
- Другой плагин после сенсора может изменить проверенные данные. Передача состояния
  из hook не даёт гарантии против таких последующих мутаций.
- Сохранение всей истории и запросов увеличивает память, место на диске и будущий
  трафик классификатора. В этом MVP история не обрезается молча.
